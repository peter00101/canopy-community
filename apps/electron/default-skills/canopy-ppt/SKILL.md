# Canopy PPT 总控

## 这个 Skill 做什么

把「做一份 PPT」拆成六步，每步都有可检查的产物，让用户决定怎么做、做成什么样：

| 步 | 产物 | 用户能控制什么 |
|---|---|---|
| 0 需求 | 一次问清 | 主题、页数、语言、制作方式（快速 / 标准） |
| 1 调研 | `research/notes.md` | 不调研 / 轻量 / 深度 |
| 2 大纲 | `outline.json` | 逐页增删改，确认后才往下走 |
| 3 风格 | `design.json` | 风格卡 / 模板卡 / 沿用旧 PPT / 自定义 / 和 Agent 一起创造 |
| 4 制作 | `slides/pNN.svg` | 封面二选一；单页重做只动那一页 |
| 5 质检与交付 | `deck.pptx` + `qa/` | 截图复核；产物形态四选一 |

设计思想只学不搬：金字塔大纲（结论先行）、便当网格（内容驱动卡片数量）、受限 SVG 契约（每页一张矢量图，PowerPoint 能直接渲染）、密度与间距硬规则、风格卡与模板卡。**不依赖 Python、Node、任何外部前端或联网服务；调研没有搜索 Key 时用内置浏览器兜底。**

## 与其它 Skill 的分工

- **编辑已有 .pptx**：用内置 Office 工具（`OfficeInspect` / `OfficeEdit` / `OfficeBatch`）读改。本 Skill 只负责「做一份新的」。
- **guizang-ppt-skill**：用户在第 0 步选「网页 PPT」时，大纲与风格定稿后把 `outline.json` 与 `design.json` 交给它生成单文件 HTML；它有「与 canopy-ppt 联动」一节，会跳过自己的七问、按映射规则挑风格与主题色。
- **读用户材料**：Word / Excel 用 `OfficeInspect`（`mode=text` / `outline` / `query`）读，不要自己写解析脚本；PDF 直接用 Read 读取，实在读不出就请用户贴文字。
- **in-app-browser**：深度调研时按它的规范操作浏览器。
- 内置 Office 工具（`OfficeCreate` / `OfficeBatch` / `OfficeInspect`）是合成与质检的执行器。

## 工作目录约定

所有产物放在当前工作目录下的 `ppt/<slug>/`，`<slug>` 用主题的短英文或拼音加日期，例如 `ppt/q3-report-20260913/`：

```text
ppt/q3-report-20260913/
├── research/notes.md      # 调研笔记（可选）
├── outline.json           # 金字塔大纲
├── design.json            # 风格 token（配色、字体、形状语言、模板底图）
├── slides/p01.svg …       # 每页一张 SVG，1280×720
├── qa/contact.png         # 联系表截图，qa/pNN.png 单页放大
├── deck.pptx              # 合成产物
└── README.md              # 交付说明：怎么改、素材来源、未做的事
```

工作目录根下另有两处**用户资产**，Skill 升级不会碰它们：`ppt-styles/<id>.json`（你保存的风格卡，见 05「用户风格库」）与 `ppt-templates/<id>/`（你自己的模板包，结构同随包 `templates/`）。

写文件用 `Write`，读回用 `Read`。**路径一律写绝对路径**传给 Office 工具。

## Step 0 · 需求一次问清（必做）

用 `AskUserQuestion` **一次**问完，不要分多轮：

1. **主题或材料**：用户已给材料就不问，只确认；没给就问一句「主题是什么、给谁看、要达成什么」。
2. **页数**：给选项 6 / 8 / 12 / 用户指定。
3. **语言**：中文 / 英文 / 双语。
4. **制作方式**：
   - **快速**：后面所有确认点跳过，按推荐默认直接出片，只在最后交付时汇报。
   - **标准**：调研档位、大纲、风格、封面方案四处停下来让用户选。

同一次提问里顺带给出**产物形态**四选一（默认第一项）：
- 可编辑 PPTX：文字、形状、渐变、图片编成 PowerPoint 原生对象，可逐字修改；饼图扇形、折线、斜线、旋转组这类原生画不了的元素会原位嵌成矢量小图（小图本身不可逐字改，页面其余照常可编辑），结果里逐页列出；
- 高保真 PPTX：每页一张矢量 SVG 贴进 PPTX，排版最稳，文字不可逐字编辑；
- 网页 PPT：大纲与风格定稿后交给 guizang-ppt-skill（按它的「与 canopy-ppt 联动」一节接手，不重问需求）；
- 只要 SVG：交付 `slides/` 目录。

以及**图片策略**三选一（默认第一项）：只用用户提供的图 / 不用图（用形状与数据图形代替）/ 允许从网页搜图（需用户明确同意，且只在调研中顺手保存来源页的图）。**不做 AI 生图。**

快速模式只问第 1 题（主题或材料）；其余按默认：8 页、跟随用户语言、不调研（有材料）或轻量调研（无材料）、风格卡「素笺」、可编辑 PPTX、只用用户提供的图。

## Step 1 · 调研（按档位）

读 `references/01-research.md`。规则摘要：

- **不调研**：用户材料充分或主题是内部事务（周报、复盘）。
- **轻量**：搜索接口能用就用 `WebSearch`（配了 Key 时才存在），否则用内置浏览器搜必应；取 6～10 条摘要。
- **深度**：内置浏览器逐个打开来源读全文，最多 12 个来源、每个来源抽正文不超过 3000 字，写进 `research/notes.md` 并保留 URL 与访问日期。
- 调研笔记只记事实、数据、原话，每条带来源编号；大纲阶段引用编号。**调研结论不确定的地方，在笔记里标「待核」，不要写进正文当事实。**

## Step 2 · 金字塔大纲

读 `references/02-outline.md`，按其中的提示词把主题、材料摘要、调研笔记合成 `outline.json`。要点：

- 结论先行、以上统下、归类分组、逻辑递进；每页只承载一个观点。
- 每页写清 `title`、`key_message`（一句话结论）、`content`（3～5 条要点或数据）、`visual`（这页适合什么视觉：数字卡 / 对比 / 流程 / 时间线 / 图表 / 图片）、`sources`（引用编号）。
- 页数严格等于用户要求：封面 1 + 目录 1 + 内容页 N + 总结 1。

标准模式：把大纲按「第 N 页 · 标题 · 一句话结论」列成清单给用户看，用 `AskUserQuestion` 问「照此制作 / 我来改」；用户说改就改 `outline.json` 再确认一次。快速模式直接往下。

## Step 3 · 风格

读 `references/05-styles.md`。**先用 Bash `ls` 看工作目录下有没有 `ppt-styles/*.json` 与 `ppt-templates/*/pack.json`**，有就把它们排在最前面、标「你保存的」（推荐规则一样适用）。五条路，标准模式用 `AskUserQuestion` 让用户选一条：

1. **风格卡**：你保存的风格卡 + 六套现成设计系统，按主题推荐一张，其余各列一句话特征。
2. **模板卡**：`ppt-templates/` 下你自己的包 + 本 Skill `templates/` 随包的三套，读其 `pack.json` 得到底图与 token。
3. **沿用我的旧 PPT**：用户给一份 .pptx，用 `OfficeInspect mode=screenshot` 把它最干净的一页（通常是封面后的空白页或末页）截成 PNG 当底图，配色从截图取主色，字体沿用 pack 默认。
4. **自定义**：用户给主色、字体、参考图，或只说一句感觉，据此从最接近的风格卡派生（快，但仍在现成的范围里）。
5. **一起创造**：用户对现成的都不满意、或想要独一份时，进 05「共创模式」——Agent 出 2～3 个原创方向（配色、字体气质、形状语言、新装饰、封面构图），用户挑或合并，封面二选一，几轮打磨到点头为止；定稿存成风格卡，值得复用的再打成模板包。快速模式也能走这条，用户一句「我们一起设计」就够。

产出 `design.json`（结构见 05）。**封面二选一**：标准模式下先写两版封面 `slides/p01a.svg` / `p01b.svg`，用截图（见 Step 5 的方法，只截这两页）让用户选，选定后改名为 `p01.svg` 并锁定设计系统，后续每页都沿用。快速模式只出一版。

## Step 4 · 逐页制作

产物形态是「网页 PPT」时**跳过 Step 4～5**：大纲与风格确认后按「与其它 Skill 的分工」交接，交付时说明产物由哪个 Skill 生成。

读 `references/03-layout.md`（便当网格与页型）与 `references/04-svg-contract.md`（SVG 契约）。规则摘要：

- 每页一个文件 `slides/pNN.svg`，`viewBox="0 0 1280 720"`，只用契约允许的元素，文字手工断行，图片只用 data URI 或不用。产物是可编辑 PPTX 时，按 04 末尾「原生编译友好写法」写：想让哪部分能逐字改就用 rect / circle / ellipse / 水平垂直线 / text 画它；饼图、折线、图标放心用 path / polyline，它们会原位变成矢量小图。
- 先写页型草稿：在回复里列「页码 → 页型 → 卡片数与主次 → 用到的数据」，再动手写 SVG。
- **前 3 页写完先按 `references/06-qa.md` 的结构清单自检一遍**，把问题改掉再写后面的页，避免同一个错误复制到全份。
- 密度硬规则：每页正文不超过 80 个中文字（或 60 个英文单词），至少两种视觉元素，标题不超过 16 字，卡片间距不小于 20px，四周留白不小于 40px。
- 一页一写，不要在一次回复里堆多页。

## Step 5 · 质检与合成

读 `references/06-qa.md` 与 `references/07-build.md`。顺序：

1. **结构自检**：逐页过清单（越界、重叠、字号下限、对比度、每行字数、密度）。
2. **合成**：一次 `OfficeSlidesFromSvg`（`filePath` 指向 `deck.pptx`，`svgPaths` 按页序给绝对路径，产物是可编辑 PPTX 用 `mode=native`，高保真用 `mode=picture`）。返回里逐页写明原生对象数、矢量小图清单（哪个元素、为什么）与警告，原样记进 README。工具不存在时退回 `references/07-build.md` 的手工路线。
3. **自动检查**：`OfficeInspect mode=issues` 看有没有低对比度等问题；`mode=outline` 确认页数与图片数。
4. **视觉复核**：先用 Bash `mkdir -p <绝对路径>/qa`，再 `OfficeInspect mode=screenshot grid=4 outPath=<绝对路径>/qa/contact.png` 出联系表。
   - 你能看图：`Read` 打开联系表亲眼看；可疑页再 `page=N` 单独截图放大看。
   - 你看不了图（工具返回图片但你读不出内容，DeepSeek 等纯文本模型都是这种情况）：用 `VisionRelay` 把 `qa/contact.png` 交给视觉助手，`instruction` 逐条写 `references/06-qa.md` 的七项检查，让它按页码回答；`VisionRelay` 不可用就只做结构自检，并在 README 写明「未做视觉复核」。
   - **截图工具报错就把错误原文写进 README，跳过视觉复核**。不要自己找替代渲染器。
5. **修一页只动一页**：改对应的 `pNN.svg`，删掉旧 `deck.pptx` 后再调一次 `OfficeSlidesFromSvg` 整份重生成（几秒钟），再截那一页复核。
6. 通过后写 `README.md`，交付。
7. **存风格卡 / 模板包**：这次风格来自共创、沿用旧 PPT、自定义，或用户中途改过 token 时，标准模式用 `AskUserQuestion` 问一句「要不要把这套风格存成风格卡，下次直接选？」并要个名字；快速模式不问，交付时提一句「说『把这套风格存起来』就行」。保存规则见 05「用户风格库」。用户任何时候说「记住这套风格 / 存成风格卡」都照此保存。共创出来的装饰或底图值得复用时，再问一句要不要打成模板包（做法见 05 共创模式第 4 条）。

## 交付格式

最后一条回复固定包含：

- 产物路径（`deck.pptx`、`slides/`、`qa/contact.png`），页数与每页标题一行一条；
- 用了哪张风格卡或模板，图片来源；
- 这套风格存没存成风格卡；没存的话一句话说明怎么存；
- 调研来源清单（如有）；
- 「怎么改」：改文字请改对应 `slides/pNN.svg` 后让我重新合成；要原生可编辑版本时怎么办；
- 如实列出没做的事（例如用户要图但没给图、某条数据待核）。

## 失败兜底

- `OfficeCreate` / `OfficeBatch` 报错：先把错误原文给用户看，再交付 `slides/*.svg` 与 `qa/`，说明 PPTX 未合成。
- 截图工具不可用：交付前告知未做视觉复核，只做了结构自检。
- 浏览器与搜索都不可用：调研档位降为「不调研」，并告知。
- 任何一步用户中途改需求：回到对应的产物改，不推倒重来；已锁定的封面与设计系统不动。

## 硬性禁令

- 不要生成图片，不要编造数据；大纲里没有来源的数字要在 README 标明「未经核实」。
- 不要下载依赖、不要跑 pip / npm / npx，本 Skill 零外部依赖。
- **不要探测或调用本机的 Python、Node、Playwright、Chrome、ImageMagick 等来渲染或截图**；截图只有 `OfficeInspect mode=screenshot` 一条路，看图只有 `Read` 与 `VisionRelay` 两条路。
- **不要自建 HTML 预览页、不要用 `BrowserPreviewOpen` / `BrowserScreenshot` 看 PPT**：右侧浏览器打开的本地页面里相对路径图片会碎，只会制造噪音。
- Bash 只用于 `mkdir -p`、`ls`、`grep` 检查 SVG 文本，不用于任何渲染、转换、安装。
- 不要把用户材料原文整段搬上页面，每页要提炼。
- 不要跳过 Step 0 的提问就开工，除非用户已经把主题、页数、方式一次说清。
